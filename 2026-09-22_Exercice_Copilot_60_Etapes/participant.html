Durées adaptables selon le rythme du groupe — l'important est de terminer chaque niveau avant de passer au suivant.

Remplissez ce document au fil des 60 étapes, sur le projet codebase/ (ouvrez codebase/index.html dans votre navigateur, et le dossier codebase/ dans votre éditeur). Pour chaque étape : réalisez ce qui est demandé avec GitHub Copilot (inline, Chat, Edit/Agent mode...), puis notez brièvement ce que vous avez fait ou observé dans le champ prévu. Le niveau Débutant pose les bases, l'Intermédiaire ajoute la personnalisation et la qualité, l'Expert couvre agents, skills, MCP et l'automatisation. À la fin, cliquez sur « Exporter en PDF » (en haut à droite) et remettez le fichier au formateur.

🔒 Aucune donnée réelle : le projet codebase/ est entièrement fictif. 👀 Relisez toujours une proposition de Copilot avant de l'accepter.

🟢 Niveau Débutant

Installation, interface, premières suggestions, Copilot Chat, variables de contexte, commandes slash de base, prompt engineering de base.

Phase 1 — Installation et interface

1

Installer / vérifier Copilot

~2 min

Dans VS Code, ouvrez l'onglet Extensions et vérifiez que GitHub Copilot et GitHub Copilot Chat sont installées et activées, puis connectez-vous avec votre compte GitHub si ce n'est pas déjà fait.

2

Ouvrir le projet

~2 min

Ouvrez le dossier codebase/ dans VS Code (File → Open Folder).

3

Icône Copilot et statut

~1 min

Cliquez sur l'icône Copilot dans la barre d'état en bas de VS Code.

Phase 2 — Premier contact avec le chat et les modèles

4

Ouvrir Copilot Chat

~2 min

Ouvrez Copilot Chat (icône dans la barre d'activité, ou Ctrl+Alt+I). Cliquez sur le sélecteur de modèle en bas du panneau et notez le modèle actif par défaut.

5

Comparer deux modèles

~3 min

Posez la même question à deux modèles différents (via le sélecteur) : « Explique en une phrase ce qu'est une variable CSS. »

Explique en une phrase ce qu'est une variable CSS.

Phase 3 — Suggestions inline (ghost text)

6

Première suggestion inline

~2 min

Ouvrez js/app.js, placez le curseur en fin de fichier, et tapez ce commentaire puis attendez :

// fonction qui calcule le nombre de tâches en retard
7

Accepter / annuler

~1 min

Appuyez sur Tab pour accepter la suggestion de l'étape précédente, puis Ctrl+Z pour l'annuler.

8

Suggestions alternatives

~1 min

Retapez le commentaire de l'étape 6, puis utilisez Alt+] et Alt+[ pour parcourir plusieurs propositions.

Phase 4 — Copilot Chat : les bases

9

Question générale (mode Ask)

~2 min

En mode Chat « Ask », posez une question générale sans référence au projet.

Quelle est la différence entre let et const en JavaScript ?

Phase 5 — Variables de contexte #

10

#file + /explain

~2 min

Dans le Chat, ciblez un fichier précis avec #file puis demandez une explication :

#file:index.html /explain
11

#selection

~2 min

Sélectionnez le bloc <section class="board">...</section> dans index.html, puis dans le Chat :

#selection Explique ce bloc et à quoi sert chaque colonne.
12

#codebase

~2 min

Posez une question transversale sur tout le projet avec #codebase :

#codebase Où est définie la classe .card et quels fichiers l'utilisent ?

Phase 6 — Commandes slash

13

/fix sur le bug de date

~3 min

Ouvrez js/app.js, sélectionnez la fonction formatDate, ouvrez le Chat inline (Ctrl+I) ou le panneau Chat, et lancez :

/fix la date affichée est décalée d'un mois par rapport à la date d'échéance saisie
14

/tests sur une fonction pure

~3 min

Sélectionnez la fonction libellePriorite puis :

/tests
15

/doc sur une fonction

~2 min

Sélectionnez creerCarteTache puis :

/doc

Phase 7 — Raccourcis et inline chat

16

Panorama des raccourcis

~2 min

Repérez et testez : Ctrl+Enter (ouvrir plusieurs suggestions dans un panneau), Ctrl+I (chat inline), Ctrl+Alt+I (ouvrir/fermer le panneau Chat).

17

Inline chat sur une ligne

~2 min

Dans css/legacy-styles.css, placez le curseur sur la règle .old-badge-low, ouvrez l'inline chat (Ctrl+I) et demandez :

Remplace les valeurs magiques par les variables définies dans variables.css

Phase 8 — Prompt engineering de base

18

Prompt vague

~3 min

Dans le Chat, posez volontairement une question vague :

Améliore mon CSS
19

Prompt structuré

~2 min

Reformulez avec un prompt structuré (rôle + fichier ciblé + contrainte + format de réponse) :

#file:css/legacy-styles.css Tu es un(e) expert(e) CSS. Liste, sous forme de tableau, les 3 principaux problèmes de ce fichier (nom du problème, ligne, impact), sans réécrire le code.

Phase 9 — Bilan débutant

20

Bilan niveau débutant

~3 min

Faites le point avant de passer au niveau intermédiaire.

🟡 Niveau Intermédiaire

Edit / Agent mode multi-fichiers, nettoyage et fiabilisation du code existant, personnalisation de Copilot (instructions, prompt files, AGENTS.md), choix de modèle, qualité et sécurité.

Phase 10 — Edit mode et Agent mode

21

Découvrir Edit / Agent mode

~5 min

Basculez le Chat en mode Edit (ou Agent selon la version de VS Code), ajoutez index.html et js/app.js au contexte, et observez l'interface (liste de fichiers, boutons Keep/Undo).

22

Fonctionnalité multi-fichiers

~8 min

Toujours en mode Edit/Agent, avec index.html et js/app.js en contexte :

Relie le formulaire de index.html à creerCarteTache() : à la soumission, empêche le rechargement de page, construis l'objet tâche à partir des champs du formulaire, ajoute la carte dans la colonne "À faire" et incrémente son compteur .count.
23

#terminal et #problems

~4 min

Ouvrez le panneau Problems de VS Code (s'il y a des avertissements), puis dans le Chat :

#problems Explique les avertissements listés et propose une correction pour chacun.

Phase 11 — Nettoyer et fiabiliser le code existant

24

Refactorer le CSS hérité

~6 min

Sur css/legacy-styles.css entier (pas seulement une règle) :

#file:css/legacy-styles.css #file:css/variables.css Réécris ce fichier en supprimant les !important et les valeurs magiques, en réutilisant les variables de variables.css. Garde les mêmes noms de classes pour ne rien casser ailleurs.
25

Tests sur cas limites

~5 min

Complétez les tests de l'étape 14 avec des cas limites :

#file:js/app.js Ajoute des tests pour formatDate() avec : une date vide, une date invalide, et le 31 décembre (changement d'année).
26

Revue de code critique

~5 min

Demandez une revue exigeante, sans complaisance :

#file:js/app.js Fais une revue de code sans complaisance : bugs restants, risques de sécurité, points de lisibilité. Classe chaque point par gravité.
27

Debug guidé

~6 min

Formulez un prompt de debug complet (contexte + comportement observé + comportement attendu), par exemple sur un champ de date vide :

Contexte : formulaire de index.html, champ dueDate laissé vide. Comportement observé : la carte créée affiche une date incorrecte au lieu de "Sans échéance". Comportement attendu : afficher "Sans échéance" quand le champ est vide. Propose une correction ciblée.

Phase 12 — Personnaliser Copilot pour le projet

28

Créer copilot-instructions.md

~5 min

Créez le fichier .github/copilot-instructions.md à la racine de codebase/ avec des règles de projet (langue, style de code, conventions).

Rédige un fichier copilot-instructions.md pour ce projet : réponses en français, JavaScript vanilla sans framework, noms de fonctions en français comme le reste du fichier, toujours proposer un test pour une nouvelle fonction.
29

Vérifier l'effet des instructions

~3 min

Reposez une question neutre en anglais dans le Chat et observez si la réponse revient en français.

Add a function that counts tasks by priority
30

Instructions ciblées (applyTo)

~4 min

Créez un fichier .github/instructions/css.instructions.md avec un en-tête applyTo: "css/**" et une règle spécifique au CSS.

applyTo: "css/**" Toujours utiliser les variables définies dans variables.css, jamais de couleur ou de taille codée en dur.
31

Créer un prompt file réutilisable

~5 min

Créez .github/prompts/nouvelle-carte.prompt.md pour une tâche récurrente (générer une nouvelle variante de carte), puis invoquez-le avec /nouvelle-carte.

--- mode: edit --- Génère une variante compacte de .card (classe .card--compact) qui affiche uniquement le titre et le badge de priorité.
32

AGENTS.md à la racine

~4 min

Créez un fichier AGENTS.md à la racine de codebase/ décrivant comment un agent doit travailler sur ce dépôt (commandes disponibles, conventions, fichiers sensibles).

Phase 13 — Choisir le bon modèle et cadrer la sortie

33

Comparer 2 modèles sur une tâche complexe

~4 min

Demandez la même fonctionnalité (ex. filtre par priorité) à deux modèles différents et comparez.

Ajoute un filtre par priorité au-dessus du tableau : 4 boutons (Basse/Moyenne/Haute/Critique) qui montrent/masquent les cartes correspondantes.
34

Contraindre le format de sortie

~3 min

Redemandez une analyse en imposant un format de sortie strict.

#file:js/app.js Liste les fonctions de ce fichier. Réponds uniquement avec un tableau JSON : [{"nom":..., "role":...}]. Aucun texte hors du JSON.

Phase 14 — Vue d'ensemble et qualité

35

@workspace

~3 min

Posez une question d'architecture globale avec @workspace :

@workspace Comment les 3 pages du projet partagent-elles leurs styles, et où faudrait-il ajouter une nouvelle page ?
36

Documentation automatique

~4 min

Générez une section de documentation à ajouter au README du projet.

#file:js/app.js Rédige une section "## Script" pour le README, qui liste les fonctions disponibles et leur rôle.
37

Audit accessibilité

~5 min

Demandez un audit a11y sur index.html en vous appuyant sur la checklist du projet, puis appliquez 2 corrections.

#file:index.html #file:docs/checklist-accessibilite.md Audite cette page selon la checklist. Liste les manquements puis corrige les 2 plus importants.
38

Revue de sécurité (XSS)

~5 min

Demandez une revue de sécurité ciblée sur la fonction qui insère du contenu utilisateur dans le DOM.

#file:js/app.js Si demain le titre ou la description d'une tâche provenait d'une API externe non fiable, quels risques ce code présente-t-il et comment les corriger ?
39

Message de commit

~3 min

Générez un message de commit décrivant les changements de la session (Conventional Commits).

Résume en un message de commit (Conventional Commits) les changements : correction du bug de date, ajout de la logique de formulaire, refactor du CSS hérité, ajout des instructions Copilot.

Phase 15 — Bilan intermédiaire

40

Bilan niveau intermédiaire

~4 min

Faites le point avant de passer au niveau expert.

🔴 Niveau Expert

Agents (cloud, personnalisés, sous-agents), Skills, MCP, plugins, hooks, workflows agentiques, prompt engineering avancé, gouvernance, Copilot CLI, capstone.

Phase 16 — Agents : cloud, personnalisés, sous-agents

41

Découvrir le Cloud / coding agent

~5 min

Explorez l'agent asynchrone (Cloud agent / coding agent en arrière-plan, accessible depuis GitHub.com ou VS Code) : décrivez une tâche déléguée que vous pourriez lui confier sans supervision directe.

42

Créer un agent personnalisé

~6 min

Créez un mode de chat personnalisé (custom chat mode) « Relecteur CSS », avec des instructions et un périmètre d'outils restreint (lecture seule par exemple).

Nom : Relecteur CSS Instructions : Tu relis uniquement le CSS de ce projet. Tu ne modifies jamais de fichier, tu listes des recommandations classées par gravité. Outils : lecture de fichiers uniquement.
43

Sous-agent / handoff

~6 min

Configurez un agent principal qui délègue une sous-tâche à un agent spécialisé (handoff), par exemple : l'agent principal code la fonctionnalité, puis transmet (« handoff ») au « Relecteur CSS » de l'étape 42 pour validation avant de conclure.

Phase 17 — Skills

44

Créer une Skill

~6 min

Créez skills/validation-taskboard/SKILL.md décrivant une procédure à suivre avant toute modification du formulaire (ex. vérifier les labels, les types de champs, l'ordre de tabulation).

--- name: validation-taskboard description: Procédure à suivre avant toute modification du formulaire de TaskBoard. --- 1. Vérifier que chaque champ a un <label for=...>. 2. Vérifier le type des champs (date, select...). 3. Vérifier l'ordre de tabulation logique. 4. Ne jamais retirer l'attribut required du titre.
45

Tester l'invocation de la skill

~4 min

Demandez une modification du formulaire en faisant explicitement référence à la skill.

#file:skills/validation-taskboard/SKILL.md Je veux ajouter un champ "assigné à" au formulaire. Applique la procédure de la skill avant de proposer du code.

Phase 18 — MCP, plugins, hooks, workflows

46

Configurer et utiliser un serveur MCP

~6 min

Configurez un serveur MCP (ex. Context7) dans les paramètres de Copilot, puis utilisez-le explicitement dans un prompt.

Quelles sont les recommandations actuelles pour l'attribut loading="lazy" sur une image ? use context7
47

Explorer un plugin de l'écosystème

~4 min

Parcourez le dépôt communautaire github/awesome-copilot et identifiez un plugin, une instruction ou un prompt file pertinent pour ce projet.

48

Créer un hook

~5 min

Décrivez (ou configurez) un hook déclenché avant un commit, qui rappelle de relire le diff généré par Copilot.

Déclencheur : avant chaque commit. Action : afficher un rappel "As-tu relu et testé le code généré par Copilot dans ce diff ?" et bloquer si la checklist docs/checklist-accessibilite.md n'a pas été consultée.
49

Workflow agentique

~6 min

Concevez un workflow agentique déclenché automatiquement (ex. à chaque ouverture de Pull Request) qui fait relire le diff par un agent.

on: pull_request steps: 1. Charger le diff de la PR. 2. Lancer l'agent "Relecteur CSS" si des fichiers .css sont modifiés. 3. Publier les recommandations en commentaire de la PR.

Phase 19 — Orchestration bout en bout

50

Orchestrer agent > skill > MCP

~8 min

Sur une fonctionnalité complète (ex. ajout d'un champ « tags » au formulaire), enchaînez : l'agent applique la skill de validation (étape 44), consulte le MCP si besoin d'une bonne pratique à jour, puis produit le code final.

#file:skills/validation-taskboard/SKILL.md Ajoute un champ "tags" (texte libre, séparés par des virgules) au formulaire. Applique d'abord la procédure de la skill, puis vérifie une bonne pratique d'accessibilité pour ce type de champ avant de coder. use context7

Phase 20 — Prompt engineering avancé

51

Chain-of-thought guidée

~5 min

Demandez à Copilot de raisonner étape par étape avant de conclure, sur un choix d'architecture.

Faut-il stocker les tâches en localStorage ou dans un fichier JSON statique ? Raisonne étape par étape (contraintes, avantages, inconvénients de chaque option) avant de conclure.
52

Format de sortie strict (diff)

~5 min

Demandez une modification en exigeant un format de diff unifié, sans explication autour.

#file:js/app.js Ajoute une fonction supprimerTache(id) qui retire une carte du DOM. Réponds uniquement avec un diff au format unifié (--- / +++ / @@), sans aucun texte autour.
53

Gérer un contexte trop long

~4 min

Discutez des stratégies à appliquer quand le projet dépasse la fenêtre de contexte du modèle (beaucoup plus de fichiers qu'ici).

54

Sobriété : coût et choix du modèle

~4 min

Comparez un prompt large (« améliore tout le projet ») à un prompt ciblé (une fonction précise) en termes de temps de réponse et de pertinence, puis choisissez le modèle le plus adapté à une tâche simple vs une tâche complexe.

Phase 21 — Sécurité et gouvernance

55

Checklist de revue obligatoire

~4 min

Rédigez une checklist courte de revue obligatoire avant tout merge de code généré par Copilot.

56

Charte d'usage pour une équipe

~4 min

Rédigez une charte courte (do's / don'ts) pour l'usage de Copilot au sein d'une équipe.

Phase 22 — Copilot CLI

57

Utiliser Copilot en ligne de commande

~5 min

Dans un terminal, testez la commande CLI de Copilot pour expliquer ou suggérer une commande shell.

gh copilot suggest "trouver tous les fichiers CSS contenant !important"

Phase 23 — Capstone et bilan

58

Capstone : fonctionnalité complète

~15 min

En mobilisant tout l'arsenal (Chat, Edit/Agent mode, instructions, skill, tests), construisez de bout en bout une fonctionnalité complète : persistance localStorage des tâches créées ET filtre par priorité fonctionnel.

#file:js/app.js #file:skills/validation-taskboard/SKILL.md Objectif : les tâches créées via le formulaire persistent après rechargement (localStorage) et un filtre par priorité (4 boutons) permet de n'afficher qu'une catégorie. Applique la skill, propose un plan en 3 étapes, puis code chaque étape avec un test à l'appui.
59

Auto-évaluation du diff final

~5 min

Demandez à Copilot d'auditer lui-même le résultat du capstone.

#file:js/app.js Audite le code final : que resterait-il à améliorer si ce projet devait passer en production (hors du cadre pédagogique) ?
