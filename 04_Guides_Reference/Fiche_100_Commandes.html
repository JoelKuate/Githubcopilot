Avant toute commande — la règle du guide s'applique d'abord : données C2 au maximum, jamais de donnée réelle, jamais de module critique de sécurité, et relecture humaine systématique. Une commande qui simplifie le travail ne change rien à ce cadre.

A · 1 à 16Variables de contexte # — de quoi vous parlez

Elles désignent ce que Copilot doit regarder. C'est la famille la plus rentable : une bonne variable vaut mieux qu'un long paragraphe. Ordre de préférence : #selection, puis #file, puis #codebase.

#CommandeCe qu'elle ajoute au contexteStatut
1#fileUn fichier précis, désigné par son nom. Le réflexe de base.pratiqué
2#selectionLe code actuellement sélectionné dans l'éditeur. Le plus précis, le moins cher.pratiqué
3#codebaseUne recherche dans tout le projet. Coûteux : à réserver aux questions transversales.pratiqué
4#folderUn dossier entier. Très coûteux, à réserver à une vraie question d'ensemble.référence
5#problemsLes erreurs et avertissements remontés par l'éditeur.pratiqué
6#changesLes modifications en cours, non encore validées. La plus sous-utilisée.pratiqué
7#testFailureLes informations sur le dernier test en échec.pratiqué
8#terminalSelectionLe texte sélectionné dans le terminal.référence
9#terminalLastCommandLa dernière commande lancée et sa sortie.référence
10#fetchLe contenu d'une page web, à partir de son adresse.référence
11#githubRepoUne recherche de code dans un dépôt GitHub donné.référence
12#blockLe bloc courant, d'après la position du curseur.pratiqué
13#lineLa ligne courante.pratiqué
14#commentLe commentaire courant.pratiqué
15#sym · #path · #projectLe symbole courant, le chemin du fichier, le contexte du projet.pratiqué
16#function · #classLa fonction, la méthode ou la classe courante. Sans objet sur un projet HTML/CSS.pratiqué
Source : GitHub Docs, « Chat cheat sheet » et VS Code Docs, « Chat context ».

F · 55 à 60Permissions et modes — à connaître, à ne pas utiliser
