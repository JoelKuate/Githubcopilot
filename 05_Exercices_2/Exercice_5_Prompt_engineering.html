Exercice pratique 5 · prompt engineering

Bien demander : l'atelier du prompt

GitHub Copilot pour débutants — Transactis · terrain TaskFlow

Durée50 minutes
FormatIndividuel, comparaisons en binôme
Pistesles deux
Tâches12 tâches pratiques
Objectif — la différence entre une réponse inutilisable et une réponse exploitable tient presque toujours à la demande, pas au modèle. Cet exercice se fait entièrement sur TaskFlow, avec des demandes que vous réutiliserez dès lundi.
Les quatre blocs — Contexte (de quoi on parle) · Tâche (un verbe d'action) · Contraintes (ce qu'il ne faut pas faire) · Résultat attendu (la forme de la réponse).

1Mesurer le point de départ

Dans une conversation neuve, envoyez exactement ceci, sans rien ajouter :

ameliore ce fichier
ObservationMa mesure
Nombre de lignes modifiées proposées
Fichiers touchés
Temps qu'il me faudrait pour relire
Est-ce que je peux défendre chaque ligne ?

2Ajouter un seul bloc : le contexte

#file css/legacy-styles.css     (ou #file RapportLegacy.java)
ameliore ce fichier

3Ajouter la tâche — un verbe d'action précis

#file css/legacy-styles.css
Remplace les couleurs et espacements ecrits en dur par les jetons de
css/variables.css.

4Ajouter les contraintes — le bloc le plus oublié

#file css/legacy-styles.css
Remplace les couleurs et espacements ecrits en dur par les jetons de
css/variables.css.
Contraintes : garder EXACTEMENT le meme rendu visuel ; ne pas toucher aux
autres blocs ; aucun JavaScript ; ni selecteur par identifiant, ni !important.
C'est ici que se joue la qualité. Une contrainte est presque toujours une phrase négative : ce qu'il ne faut pas faire.

5Ajouter le résultat attendu — la forme de la réponse

[... les trois blocs precedents ...]
Resultat attendu : le bloc modifie seul, sans reecriture du fichier, avec un
commentaire d'une ligne, et la liste de ce que je dois verifier moi-meme.

6Demander un format précis — trois fois la même question

Même question, trois formats de réponse imposés. Comparez l'utilité.

A :  Explique-moi ce bloc.
B :  Explique-moi ce bloc en trois puces maximum, sans code.
C :  Explique-moi ce bloc sous forme de tableau : element | role | ou c'est utilise.

7Donner un exemple plutôt qu'une explication

Je veux une mention lisible a la place d'un nombre de jours.
Exemples attendus :
   5   ->  « echeance dans 5 jours »
   0   ->  « echeance aujourd'hui »
  -3   ->  « echeance depassee depuis 3 jours »
Applique cette regle. Donne uniquement la partie modifiee.

8Écrire à Copilot dans le code, pas dans le chat

Collez ce commentaire dans le fichier, à l'endroit exact où vous voulez le code, puis Entrée.

<!-- Carte de demande : reference, badge de priorite en haut a droite,
     objet sur deux lignes maximum, echeance en bas.
     Classes prefixees tf-, aucune couleur en dur. -->
Deux écritures, deux usages — dans le code, le prompt est un commentaire court à l'impératif ; dans le chat, c'est une demande structurée en quatre blocs. Le risque diffère aussi : accepter sans lire d'un côté, répondre hors sujet de l'autre.

9Relancer plutôt que tout redemander

Sur une réponse qui ne convient pas, comparez deux façons de réagir.

A :  [je reformule toute ma demande depuis le debut]
B :  Ta proposition touche aussi le bloc du pied de page. Reprends uniquement
     le bloc de l'encart, le reste etait bon.

10Transformer trois demandes floues — en autonomie

Demande floueMa version en quatre blocs
« rends ça plus propre »
« corrige le bug »
« documente ce fichier »

11Le prompt de sécurité — anonymiser avant d'envoyer

On vous demande de l'aide sur une erreur de production. Vous ne pouvez transmettre aucune donnée réelle.
Exemple a NE PAS envoyer :
   Erreur sur la demande de [nom] (matricule [xxxxx]), service Comptabilite,
   lors de l'appel a srv-prod-02.interne/api/v2/demandes avec le jeton eyJ...
La sécurité et la qualité vont dans le même sens : la version anonymisée est plus courte, coûte moins de tokens, et donne une meilleure réponse.

12Mon prompt réutilisable

Écrivez le prompt que vous garderez, celui que vous recollerez chaque semaine sur vos vrais projets.

Bonus — ce prompt est exactement ce qu'on range dans un fichier de prompt ou une skill. C'est l'objet de l'exercice 6.

Bilan de l'exercice 5

  • J'ai mesuré l'écart entre une demande floue et une demande à quatre blocs.
  • J'ai écrit au moins une contrainte négative dans chacune de mes demandes.
  • J'ai imposé un format de réponse au moins une fois.
  • J'ai relancé sur le point qui coince plutôt que tout redemander.
  • J'ai un prompt type, écrit avec mes conventions, prêt pour lundi.
