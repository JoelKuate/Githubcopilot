Exercice pratique 3 · sur le programme

Faire évoluer le programme, sous contrôle

GitHub Copilot pour débutants — Transactis · terrain TaskFlow

Durée50 minutes
FormatIndividuel
Pisteshtml/cssjava
Tâches10 tâches pratiques
Objectif — transformer un besoin exprimé en français en une modification dont vous pouvez rendre compte.
Les quatre temps — reformuler le besoin en une phrase vérifiable · localiser le fichier · décrire le comportement voulu, pas l'implémentation · relire ligne à ligne avant d'appliquer.

1Le besoin, tel qu'un utilisateur le formule

« Sur la fiche d'une demande, je veux voir tout de suite si l'échéance est proche. »
C'est un besoin, pas une spécification. Personne ne vous dira quoi coder.
Test — si votre phrase contient déjà une solution technique (« ajouter une classe rouge »), elle est mauvaise. Recommencez par le résultat visible.

2Localiser, avec l'aide de Copilot

#codebase
Je veux modifier l'affichage de l'echeance sur la fiche d'une demande.
Quels fichiers sont concernes, et lequel est le point d'entree ?
Reponds par une liste de fichiers, sans code.

3Écrire la demande en quatre blocs

Contexte · Tâche · Contraintes · Résultat attendu. Trois à quatre phrases suffisent.
Contraintes minimales à faire figurer : html/css HTML et CSS uniquement, aucun JavaScript, aucune couleur hors variables.css, réutiliser les classes existantes, ne pas toucher au tableau de index.html. java aucune valeur magique, java.time, signatures conservées, sortie lisible en console.

4Obtenir la proposition — et ne rien appliquer

Envoyez la demande. Ne cliquez pas sur Appliquer. Lisez d'abord.

Ce que je lisMa réponse
Le nom du fichier en tête du bloc est-il le bon ?
Combien de lignes sont modifiées ?
Y a-t-il du code que je ne comprends pas ?
Les fichiers listés comme consultés sont-ils ceux que j'attendais ?

5La grille de relecture, point par point

PointConforme ?Ce que je refuse
Périmètre — un bloc non concerné a-t-il été touché ?
Conventions — préfixes, jetons, noms en français
Non demandé — JavaScript, bibliothèque, dépendance ajoutée
Accessibilité — bouton resté bouton, label présent, info pas portée par la seule couleur
Cas limites — texte long, valeur absente, écran étroit

6Appliquer, puis vérifier sur les deux cas

html/css detail.html — échéance proche, puis detail-depassee.html — échéance dépassée.
java ./run.sh fiche DEM-2026-0112 puis ./run.sh fiche DEM-2026-0107.

Attendu — les deux cas sont lisibles, et l'information ne repose pas uniquement sur la couleur.

7Le cas limite qu'on oublie toujours

Que se passe-t-il si l'échéance est aujourd'hui ? Vérifiez, et corrigez si nécessaire.

Le cas « echeance aujourd'hui » n'est pas couvert par ma modification.
Ajoute-le, sans changer les deux autres cas, et donne-moi uniquement
la difference.

8Une deuxième évolution, en autonomie

Nouveau besoin : « Dans le tableau, je veux repérer d'un coup d'œil les demandes clôturées. »

Reprenez les quatre temps, seul, sans relire les tâches précédentes.

9Vérifier le périmètre global

#changes
Resume tout ce que j'ai modifie aujourd'hui, fichier par fichier.
Signale ce qui sort des deux besoins : « echeance visible sur la fiche » et
« demandes cloturees reperables dans le tableau ».

10Rendre compte en trois phrases

Bilan de l'exercice 3

  • J'ai reformulé le besoin en une phrase vérifiable, sans solution technique dedans.
  • J'ai décrit le comportement voulu, pas l'implémentation.
  • J'ai relu la proposition avant de l'appliquer, avec la grille.
  • J'ai testé les trois cas : proche, dépassée, aujourd'hui.
  • Je peux nommer ce que j'ai refusé, sur chacune des deux évolutions.
