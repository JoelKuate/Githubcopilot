Exercice pratique 6 · skills et autres usages

Skills, instructions et autres usages de GitHub Copilot

GitHub Copilot pour débutants — Transactis · terrain TaskFlow

Durée55 minutes
FormatIndividuel
Pistesles deux
Tâches12 tâches pratiques
Objectif — arrêter de répéter les mêmes contraintes à chaque demande. Vous allez écrire, tester et faire échouer une instruction de dépôt, une instruction ciblée et une skill, sur TaskFlow.
Préparation — dans 02_Codebase_TaskFlow, renommez le dossier dossier-github-a-renommer en .github. Rechargez la fenêtre de l'éditeur.
Règle Transactis qui s'applique aussi ici — ces fichiers sont versionnés et partagés avec toute l'équipe. Aucun secret, aucune adresse de serveur interne, aucune donnée réelle ne doit y figurer. Ce sont des documents de projet, pas des notes personnelles.

1Mesurer l'état sans instructions

Avant de renommer le dossier, dans une conversation neuve :

#file css/components.css
Ajoute une variante compacte du badge de priorite.

2Activer les instructions et refaire la même demande

Renommez maintenant le dossier en .github, rechargez l'éditeur, ouvrez une nouvelle conversation, et envoyez exactement la même demande.

C'est tout l'intérêt du mécanisme — une page d'instructions bien écrite vaut mieux que dix prompts très longs. Vous n'avez rien à mentionner : le fichier est lu automatiquement.

3Lire ce qui pilote la réponse

Ouvrez .github/copilot-instructions.md et repérez les règles qui ont produit la différence.

Différence observéeLa règle qui l'a produite

4Ajouter votre propre règle — et la voir s'appliquer

Ajoutez une règle concrète et vérifiable à la fin de copilot-instructions.md, par exemple :

- Toute nouvelle classe CSS doit etre documentee par un commentaire d'une ligne
  indiquant sur quelles pages elle est utilisee.
Une règle du type « écris du code de qualité » n'a aucun effet et occupe de la place. Le test : peut-on vérifier objectivement qu'elle est respectée ?

5Une instruction qui ne vaut que pour certains fichiers

Ouvrez .github/instructions/css.instructions.md et lisez son en-tête applyTo.

---
name: 'Conventions CSS de TaskFlow'
description: 'Regles de style pour toutes les feuilles CSS du projet'
applyTo: '**/*.css'
---

Créez à côté un second fichier legacy.instructions.md avec applyTo: 'css/legacy-styles.css' et une règle propre au code hérité.

Les couches s'additionnent — organisation, dépôt, fichier ciblé, puis votre demande. Il n'y a pas de gagnant unique : c'est pourquoi il ne faut pas écrire d'instructions contradictoires.

6Lire une skill existante

Ouvrez .github/skills/revue-taskflow/SKILL.md.

Champ de l'en-têteSa valeur iciÀ quoi il sert
name
description
La description est le champ qui compte le plus : c'est elle qui décide du chargement automatique. Mal écrite, la skill ne se déclenche jamais — ou se déclenche à contretemps.

7Déclencher la skill, des deux façons

A · en commande :   /revue-taskflow   puis la proposition a relire
B · automatiquement : « Relis cette modification avant que je l'accepte. »
Si la skill est ignorée, la description ou les étapes sont trop vagues. C'est le diagnostic n° 1, et il vaut aussi pour vos futures skills.

8Écrire votre propre skill

Créez .github/skills/verifier-accessibilite/SKILL.md. Partez de ce squelette et remplissez-le.

---
name: verifier-accessibilite
description: [quand faut-il l'utiliser ? c'est ce texte qui declenche la skill]
---

# [titre]

Pour chaque page, verifier dans cet ordre et repondre point par point :

1. [...]
2. [...]
3. [...]

Terminer par la liste de ce que je dois verifier moi-meme au clavier.

9Tester sa skill — et la faire échouer

Nouvelle conversation. Appelez votre skill sur nouvelle-demande.html.

TestRésultat
La skill se déclenche-t-elle en commande ?
Se déclenche-t-elle automatiquement, sur une demande proche ?
La réponse suit-elle mes étapes, dans l'ordre ?
Une étape est-elle systématiquement sautée ?

10Instruction ou skill : trancher sur des cas réels

Ce que je veuxInstruction, ou skill ? Pourquoi
« Aucune couleur hors variables.css »
« Ma grille de relecture avant d'accepter une proposition »
« Réponds toujours en français »
« Les conventions propres aux fichiers de test »
Le test — si la règle doit s'appliquer même quand vous avez oublié d'y penser, c'est une instruction. Si elle correspond à un moment précis de votre travail, c'est une skill.
