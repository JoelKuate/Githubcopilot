Exercice pratique 1 · sur le programme

Comprendre un programme qu'on n'a pas écrit

GitHub Copilot pour débutants — Transactis · terrain TaskFlow

Durée40 minutes
FormatIndividuel, puis mise en commun
Pisteshtml/cssjava
Tâches10 tâches pratiques
Objectif — le premier usage professionnel de Copilot n'est pas d'écrire du code, c'est de comprendre celui qu'on n'a pas écrit. À la fin de cet exercice, vous savez cibler le bon niveau de question, et surtout vérifier ce que l'assistant vous répond.
Règle du jour — vous ne modifiez aucun fichier pendant cet exercice. Que de la lecture.

1Ouvrir et regarder avant de demander

html/css Ouvrez index.html dans un navigateur et about.html. java Lancez ./run.sh puis ./run.sh tests.

Attendu — vous savez dire, sans Copilot : combien il y a de demandes, combien sont urgentes, combien d'échéances sont dépassées.
On ne pose jamais une question à Copilot sur un code qu'on n'a pas au moins regardé trente secondes. Sinon on ne peut pas juger la réponse.

2Niveau fichier — le rôle et les dépendances

#file css/components.css          html/css
#file RechercheUtils.java         java
/explain
Public : un developpeur qui decouvre ce projet aujourd'hui.
Reponds en cinq lignes maximum. Ne propose aucune modification.
Attendu — le rôle du fichier, ce qu'il expose, et sa place par rapport aux autres.

3Niveau bloc — le plus rentable

Sélectionnez html/css le bloc .tf-badge et ses quatre variantes — java la méthode filtrerDemandes. Puis :

#selection
Que fait exactement ce bloc, et ou est-il utilise dans le projet ?
Trois phrases. Aucune correction.

4Vérifier la réponse — le geste central

Allez vérifier vous-même l'affirmation de la tâche 3, dans le code et à l'écran.

Point à vérifierVrai / FauxOù je l'ai vérifié
Les fichiers cités existent
Les noms cités existent vraiment
Le comportement décrit correspond à l'écran
Signal d'alerte n° 1 — une explication qui décrit une gestion d'erreur, un cas limite ou un comportement « responsive » que vous ne trouvez pas dans le code. C'est le cas d'invention le plus courant.

5Niveau ligne — lever un blocage précis

Placez le curseur sur html/css la ligne --tf-couleur-accent de css/variables.css — java la ligne de calcul de joursRestants.

#line
Explique cette ligne, et dis-moi ou sa valeur est reutilisee dans le projet.

6Comparer deux niveaux de question

Posez la même question à deux niveaux différents, dans deux conversations séparées.

Conversation A :  #codebase   Comment fonctionne l'affichage des priorites ?
Conversation B :  #selection  (sur le bloc des badges) Comment fonctionne l'affichage des priorites ?
A — #codebaseB — #selection
Longueur de la réponse
Précision
Vérifiable en combien de temps
À retenir — le plus petit contexte qui permet de répondre est toujours le bon. #selection avant #file, #file avant #codebase.

7Faire expliquer le code hérité

html/css css/legacy-styles.css, bloc #encartAncien — java RapportLegacy.construireRapport.

#selection
Explique ce que fait ce code, puis liste ce qui te parait discutable.
Ne corrige rien : je veux seulement comprendre.

8Trouver où quelque chose est défini

#codebase
Ou la mention « echeance depassee » est-elle produite, et sur quelles pages
apparait-elle ?
Si la réponse cite un fichier qui n'existe pas dans le projet, notez-le : c'est un exemple parfait à montrer à la mise en commun.

9Le piège du nom qui ment

java Faites expliquer joursRestants sans rien dire d'autre. html/css Faites expliquer la classe .tf-echeance--proche en demandant « à quoi sert-elle exactement ? ».

Le point clé de l'exercice — l'assistant décrit ce que le code fait, mot pour mot. Il ne dit presque jamais spontanément que le code fait autre chose que ce que son nom promet. Repérer cet écart reste votre travail.

10Restituer sans l'outil

Fermez le Chat. Expliquez le projet à votre voisin en trois phrases, sans relire vos notes.

Bilan de l'exercice 1

  • J'ai posé au moins une question à chacun des trois niveaux : fichier, bloc, ligne.
  • J'ai vérifié moi-même au moins trois affirmations de Copilot.
  • J'ai relevé au moins un écart entre l'explication et le code.
  • Je n'ai modifié aucun fichier.
