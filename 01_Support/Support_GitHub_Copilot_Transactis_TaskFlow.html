IA générative et Copilot : l'essentiel

Vingt minutes pour comprendre ce que fait la machine, et surtout ce qu'elle ne fait pas.

Fondamentaux

Ce que « générative » veut dire

  • Un programme qui produit du contenu nouveau — texte, code, image — plutôt que de classer ou de retrouver du contenu existant.
  • Il a été entraîné sur de très grands volumes de texte et de code publics, jusqu'à une date de coupure.
  • Il ne consulte pas une base de connaissances au moment où vous l'interrogez : il prédit la suite la plus probable.
  • Conséquence directe : il peut produire une réponse parfaitement formulée et parfaitement fausse.
À retenir — la qualité de forme n'est pas un indicateur de qualité de fond. C'est la raison d'être de la validation humaine exigée par la section 3 du guide.
Source : GitHub Docs, « What is GitHub Copilot? » · classification usuelle de l'IA reprise par les ressources pédagogiques d'IBM et de Google Cloud.
Vocabulaire

Qu'est-ce qu'un modèle, qu'est-ce qu'un LLM ?

  • Modèle — le résultat concret d'un entraînement : un ensemble de paramètres numériques, souvent plusieurs milliards, interrogeable. On en change comme on change d'outil.
  • LLM (grand modèle de langage) — un modèle spécialisé dans le texte et, pour Copilot, dans le code. « Grand » parce qu'il est entraîné sur des volumes massifs et compte des milliards de paramètres.
  • Une fois entraîné, un LLM ne fait qu'une seule chose : prédire le fragment suivant le plus probable, étant donné tout ce qui précède — des milliers de fois par seconde.
  • Deux modèles différents ont été entraînés séparément, sur des données différentes : ils donneront des réponses différentes à la même question, avec un coût différent.
Cette simplicité de principe explique la puissance (il a vu énormément d'exemples) et la limite : à aucun moment il n'y a vérification de véracité, seulement une continuation plausible.
Source : GitHub Docs, « What is GitHub Copilot? » · GitHub Docs, « Supported AI models in Copilot ».

Le token, unité de contexte et de facture

  • Un token est le morceau de texte que le modèle manipule : environ trois quarts d'un mot en français, un peu plus en code.
  • Le modèle ne lit jamais des phrases : il traite une suite de tokens, l'un après l'autre.
  • Tout ce que vous envoyez et tout ce que vous recevez se compte en tokens. C'est l'unité de la facture et de la sobriété — détaillée au module 8.

Fondamentaux

Ce que GitHub Copilot est

  • Un assistant de code intégré à l'éditeur, qui voit le fichier ouvert et ce que vous lui donnez comme contexte.
  • Il complète du code pendant que vous tapez, et répond à des questions dans une fenêtre de discussion.
  • Il est bon pour : expliquer du code, proposer une première version, écrire des tests, rédiger de la documentation, reformuler.
  • Il accélère un développeur qui sait où il va. Il n'apprend pas à votre place ce que fait votre code.
Source : GitHub Docs, « What is GitHub Copilot? » — docs.github.com/copilot/get-started
Fondamentaux

Ce que GitHub Copilot n'est pas

  • Ce n'est pas un moteur de vérité : il ne sait pas si votre règle métier est la bonne.
  • Ce n'est pas un testeur : générer un test n'est pas exécuter un test.
  • Ce n'est pas un relecteur habilité : la validation par un développeur référent reste obligatoire (guide, section 7).
  • Ce n'est pas un coffre-fort : ce que vous lui envoyez sort de votre poste.
  • Ce n'est pas un décideur : le guide Transactis l'interdit explicitement, section 3.
  • Ce n'est pas Copilot Chat (Microsoft 365) : celui-là sert au mail et aux documents Office, et ne voit pas votre code. Deux outils, deux périmètres.
Le piège le plus fréquent chez les débutants : confondre « ça compile » et « c'est correct ». Nous provoquerons volontairement cette erreur à l'atelier 4.

Environnement Transactis et sécurité

Passer du texte du guide aux gestes concrets : ce que je peux envoyer, ce que je ne peux pas, et qui répond de quoi.

Sécurité

La règle de classification, en une phrase

L'IA générative mise à disposition via Workplace ou GitHub ne peut recevoir que des données classifiées C2 au maximum.

  • Si vous ne savez pas quel est le niveau de classification d'une donnée, vous ne l'envoyez pas.
  • Un doute sur la classification n'est pas un problème technique : c'est une question à poser au référent sécurité.
  • Le niveau se raisonne sur le contenu réel, pas sur le nom du fichier ni sur le répertoire où il se trouve.
Contact — accompagnement-securite@transactis.fr, pour toute demande d'accompagnement ou déclaration d'usage.
Source : Guide des bonnes pratiques Sécurité — Transactis, sections 5 et 9.
Sécurité

Ce qu'il ne faut jamais soumettre

  • Des informations sensibles : données, documents, mails, codes sources relevant de ce niveau.
  • Des données personnelles non anonymisées : nom, adresse, identifiant client, coordonnées.
  • Des informations contractuelles : clauses, conditions négociées, annexes.
  • Des informations financières.
  • Des secrets techniques : clés, jetons, mots de passe, chaînes de connexion, schémas d'infrastructure.
Le réflexe piège — coller une trace d'erreur complète pour « aller plus vite ». Une trace contient souvent un chemin serveur, un identifiant de session, parfois une portion de requête avec des valeurs réelles. On extrait le message d'erreur, pas la trace.

Checklist : les six secondes avant d'envoyer

  • Est-ce que ce que je colle contient un nom, un identifiant, une valeur réelle ?
  • Est-ce que ce fichier est classé au-delà de C2, ou est-ce que je n'en sais rien ?
  • Est-ce que j'envoie plus que nécessaire pour obtenir ma réponse ?
  • Est-ce que je saurai vérifier la réponse que je vais recevoir ?
  • Est-ce que je touche à un module critique de sécurité ?
Une seule réponse gênante suffit à ne pas envoyer. Reformulez, réduisez, ou posez la question à un collègue.

Interface

Copilot n'est pas une fenêtre, c'est plusieurs surfaces

  • Dans l'éditeur — les suggestions en ligne, qui apparaissent pendant que vous tapez.
  • La vue Chat — un panneau latéral, pour poser des questions et obtenir des explications.
  • Le chat en ligne — une zone de saisie qui s'ouvre directement dans le fichier, sur la sélection.
  • Le chat rapide — une fenêtre volante, pour une question ponctuelle sans quitter le code.
  • Hors de l'éditeur — github.com, le terminal, la revue de code. Nous les verrons en module 15, en référence.
Aujourd'hui, vous travaillerez presque uniquement dans la vue Chat et le chat en ligne, en mode Question et Édition. Le mode Agent — l'assistant qui enchaîne seul lecture, modification et exécution — n'est pas disponible chez Transactis : voir module 15.

Bien demander : prompt et contexte

La différence entre une réponse inutilisable et une réponse exploitable tient presque toujours à la demande, pas au modèle.

Prompt

La structure en quatre blocs

  • Contexte — de quoi on parle : le fichier, la fonction, la situation.
  • Tâche — ce que vous voulez obtenir, en un verbe d'action précis.
  • Contraintes — ce qu'il ne faut pas faire, les conventions à respecter, les limites.
  • Résultat attendu — la forme de la réponse : du code seul, une explication, une liste, un diff.
Les quatre blocs tiennent en trois ou quatre phrases. Ce n'est pas une question de longueur, c'est une question de précision.
Les deux contraintes que les débutants oublient : dire ce qu'il ne faut pas faire, et demander le format de la réponse — code seul, liste, explication.

Crédits, modèles et sobriété

Comprendre ce qui consomme, pour arrêter de payer — en temps et en ressources — ce dont vous n'avez pas besoin.

Le modèle de facturation

Ce qui est gratuit, ce qui est facturé

Gratuit, illimité

  • Complétions de code et suggestions « next edit » pendant que vous tapez.

Consomme des AI Credits

  • Chat, mode agent, agent distant, Copilot CLI, Copilot Spaces.
  • 1 AI Credit = 0,01 $. Un budget de 1 500 credits équivaut à 15 $ de consommation possible.
  • Le coût dépend de deux facteurs : le modèle choisi, et le nombre de tokens échangés — en entrée comme en sortie.
  • Le contexte est renvoyé à chaque tour. Une conversation de trente messages coûte, à chaque nouveau message, le prix de tout ce qui précède.
  • Les tokens de sortie coûtent nettement plus cher que ceux d'entrée : « code seulement, sans explication » réduit sensiblement la facture d'une tâche répétitive.

Sobriété

Cinq gaspillages fréquents

  • Envoyer le projet entier pour une question qui porte sur douze lignes.
  • Poursuivre une conversation de trente messages au lieu d'en ouvrir une nouvelle sur le nouveau sujet.
  • Redemander la même chose en reformulant, au lieu de relancer sur le point précis qui coince.
  • Demander une réécriture complète quand trois lignes sont en cause.
  • Utiliser le modèle le plus lourd par défaut, par confort.
Un réflexe simple — nouvelle tâche, nouvelle conversation. Le contexte accumulé d'une tâche précédente pollue la réponse autant qu'il alourdit la facture.
Les quatre gestes qui paient : ouvrir les fichiers pertinents et fermer les autres ; nettoyer l'historique ; donner un exemple d'entrée et de sortie plutôt qu'un paragraphe ; rester sur le même modèle dans une conversation, car en changer casse la mise en cache du contexte.

Personnalisation

Le problème que cela résout

  • Vous répétez les mêmes contraintes à chaque demande : « en français », « sans bibliothèque », « respecte les variables ».
  • Vos collègues ne les répètent pas, ou pas de la même façon : le code généré diverge d'une personne à l'autre.
  • Un nouvel arrivant ne les connaît pas du tout.
  • La personnalisation consiste à écrire ces contraintes dans le dépôt, une fois, pour tout le monde.
C'est le meilleur rapport effort/gain de tout l'écosystème Copilot. Une page d'instructions bien écrite vaut mieux que dix prompts très longs.

MCP

MCP — connecter Copilot à vos outils

  • Le Model Context Protocol est un standard ouvert qui définit comment Copilot se connecte à des outils et des données situés en dehors de votre code.
  • Un serveur MCP expose des outils et des données selon ce protocole commun : documentation technique à jour, suivi de tickets, base de connaissances, système de fichiers restreint.

  • Le coût : chaque serveur ajouté est une porte ouverte sur des données, et une dépendance de plus. L'activation se fait toolset par toolset, selon le principe du moindre privilège.
Un serveur MCP de documentation est l'exemple le plus rentable : il évite les réponses fondées sur une version périmée d'une bibliothèque.

Synthèse

Les dix erreurs les plus fréquentes

  • Accepter une suggestion sans la lire, parce qu'elle a l'air correcte.
  • Coller une trace d'erreur complète, avec les données réelles qu'elle contient.
  • Demander « améliore » sans dire ce qui ne va pas.
  • Envoyer le projet entier pour une question portant sur une fonction.
  • Croire qu'un test généré est un test exécuté.
  • Garder une conversation ouverte toute la journée, tous sujets confondus.
  • Utiliser le modèle le plus lourd par défaut.
  • Laisser l'assistant renommer ou restructurer au-delà du périmètre demandé.
  • Documenter ce que fait le code au lieu d'expliquer pourquoi il le fait ainsi.
  • Oublier que la responsabilité de ce qui est intégré reste la vôtre.

Synthèse

Ce qu'il faut retenir

  • Le cadre d'abord. C2 au maximum, jamais de donnée sensible, jamais de module critique de sécurité.
  • Cibler avant de demander. Le plus petit contexte qui permet de répondre.
  • Quatre blocs. Contexte, tâche, contraintes, résultat attendu.
  • Lire, toujours. Une réponse bien écrite n'est pas une réponse juste.
  • Vérifier et tester. Le vert est la seule preuve.
  • Assumer. Ce que vous validez, vous le signez.
  • Pas de mode agent. Ni agent distant, ni agent personnalisé, ni délégation. Vous savez désormais dire pourquoi.
